## 🎯 Дальнейшие шаги — по влиянию на деньги (этапы 3-5 плана)

### Этап 3 — Удержание платящих
Платящий пользователь, который не возвращается в продукт — это churn через месяц.
- [ ] **Telegram-бот уведомления** (просрочка задач, смена статуса сделки, оплата) — нужен токен от BotFather, Edge Function `telegram-notify`, поле `chat_id` в профиле пользователя
- [ ] **Web Push о дедлайнах** — Service Worker уже есть (`sw.js`), добавить подписку на push API

### Этап 4 — Снижение трения в клиентских сценариях
Чем легче клиенту агентства взаимодействовать с КП — тем ценнее продукт для самого агентства (выше готовность платить).
- [ ] **Email клиенту со ссылкой на КП** при создании портала — инфраструктура Resend уже подключена, остаётся добавить шаблон и вызов
- [ ] **Онлайн-оплата аванса в клиентском портале** — виджет ЮKassa прямо в `?portal=UUID`, привязка платежа к сделке
- [ ] **Экспорт КП в PDF** — Edge Function html-to-pdf (puppeteer/wkhtmltopdf), кнопка «Скачать PDF»

### Этап 5 — Продуктивность для удержания текущих клиентов
- [x] **Реальный AI для текста КП** — код готов и задеплоен: Edge Function `ai-proposal` (Gemini API, бесплатный тариф `gemini-2.5-flash-lite`, 1000 запросов/день без карты), мок в app.js заменён на реальный вызов, `GEMINI_API_KEY` установлен в Supabase Secrets — работает в проде
- [ ] Комментарии в задачах, массовые действия в CRM, фильтры/поиск в финансах, дашборд аналитики

## 🔍 UX-аудит живого использования (сессия 2026-06-08) — ✅ завершён

Пользователь прошёлся по продукту со скриншотами и отметил конкретные места. Часть —
однозначные баги, часть — открытые дизайн-вопросы (нужна рекомендация перед правкой кода).
Все пункты разобраны и реализованы (кроме реферальной программы — решено планировать отдельно,
см. ниже). Изменения задеплоены и проверены на проде.

### Решено в этой сессии
- [x] Переключатель темы был недоступен на мобильной версии — `#themeBtn` скрыт CSS-правилом
  на мобильных экранах (`style.css:1042`), при этом в Настройках написано «тема и режим
  клиента — в шапке» (подсказка вела в никуда). Добавлен пункт «Тема» в мобильное главное
  меню (☰ → `renderMainMenuModal`, app.js)

### Решение зафиксировано — реализовано
- [x] **Лимит на AI-агента по тарифам**: на пробном (trial) — максимум **5 запросов**
  генерации КП, на платных — без ограничения. Счётчик `state.aiProposalCount` (синхронизируется
  через `agency_state`, как остальной стейт — без миграции БД, trial-агентства всегда
  на 1 пользователя по `PLANS`, гонок нет). Проверка перед вызовом `ai-proposal` —
  при исчерпании лимита тост с предложением перейти на платный план + переход в `profile`
  (`generateProposalAI`, app.js)

### Баги вёрстки — исправлено
- [x] **Финансы, мобильная версия** — два «пустых блока» внизу таблицы оказались
  `<td colspan="4"></td>` в подвале (`tfoot`) итоговых строк: на узком экране с
  горизонтальным скроллом пользователь по умолчанию видел именно эти пустые ячейки,
  а подписи «Итого»/суммы были за кадром справа. Заменено на `colspan="5"` с понятной
  подписью прямо в видимой части («Итого получено» / «Итого расходов»)
- [x] **Мобильная версия Сметы** — компактная шапка сметы и карточка позиции занимали
  слишком много места из-за того, что `.toolbar` на мобильных переключается в колонку
  (кнопки на всю ширину). Тулбары «+ Услуги/+ Пакет/Версия» и «Дублировать/Удалить»
  закреплены в строку (`flex-direction:row;flex-wrap:wrap`); поля «Комментарий для
  клиента»/«Внутренняя заметка» свёрнуты в `<details>` (раскрыты автоматически, если
  в них уже что-то написано) — карточка позиции по умолчанию заметно компактнее

### Открытые дизайн-вопросы — решены, реализовано
- [x] **Кнопка «Сохранить проект» на вкладке «Задачи» карточки сделки** — убрана (дублировала
  «Сохранить»/«Сохранить текущий», которые уже есть на вкладках Смета/CRM). Вместо неё —
  своя кнопка «+ Задача» в шапке каждой канбан-колонки (`createTask(status)` теперь
  принимает статус и создаёт задачу сразу в нужной колонке, app.js)
- [x] **«Задачи» и «Календарь» в карточке сделки — не объединять**: разные модели (канбан —
  статусная доска работы, календарь — хронология ВСЕХ дат проекта: задачи, платежи,
  расходы, дедлайн). Слияние потеряло бы платежи/расходы из обзора. Переходы между ними
  уже есть («Все задачи», клик по карточке открывает задачу) — оставлено как есть
- [x] **«Онлайн-бриф» в Настройках компании — убрано**: дублировало то, что уже полнее
  показано на странице «Брифы» (та же ссылка + копирование + список заявок от клиентов).
  Карточка из `renderProfile`/настроек компании удалена, страница «Брифы» — единственное
  и более логичное место (app.js)

### Финансы — быстрое добавление транзакции — реализовано
- [x] **Строка из двух частей «+ Поступление» / «− Расход»** — добавлена в `renderFinance`
  прямо над таблицей операций сделки: два инлайн-поля (описание + сумма) и кнопка для
  каждого типа, запись по клику или Enter, без перехода в модалку. Ожила готовая, но
  не подключённая ранее логика `quickAddPayment`/`quickAddExpense`/`setQuickField`
  (переписана на чтение прямо из `state.quick*`, без параметров — раньше была мёртвым
  кодом). Старая модалка с датой/проектом/способом оплаты не удалена — доступна по
  кнопке «⋯» рядом (детальная запись и кросс-проектное назначение остаются)

### Открытый вопрос — без изменений (не приоритет)
- [ ] **Реферальная программа** — пользователь ожидал найти её в профиле; в коде её нет
  вообще (поиск по «реферал/referral» — пусто). Решено: не делать наспех в рамках
  UX-аудита — это отдельная фича (реферальные ссылки, учёт приглашений, начисление
  бонусов/скидок, возможно — изменения в Supabase-схеме). Спланировать как отдельную
  задачу в роадмапе монетизации, когда дойдёт очередь

### Навигация — устранена путаница из трёх разных меню
- [x] **Было**: клик по логотипу открывал «Главное меню» (`renderMainMenuModal`) с одним
  набором/порядком разделов, а ☰-бургер и кнопка «Ещё» в нижней мобильной навигации —
  отдельный оверлей «Навигация» (`#mobileNavOverlay`) с другим набором/порядком (в
  «Главном меню» не было «Сметы», зато были «Новая сделка»/«Тема» — это действия, а
  не разделы; «Онлайн-брифы» вообще существовали только там). Пользователю нравится
  паттерн «клик по логотипу → меню», поэтому решили не менять его, а довести до ума
  и сделать единственным
- [x] **Стало**: «Главное меню» дополнено («Смета», «Онлайн-брифы»), порядок выстроен
  по логике пути (Сделки → Новая сделка → Смета → Пакеты → Каталог → Финансы →
  Календарь → Договора → Клиенты → Онлайн-брифы → База знаний → Настройки → Тема →
  Профиль). Бургер и «Ещё» теперь тоже открывают «Главное меню» (`app.openMainMenu`)
  — отдельный оверлей `#mobileNavOverlay` и его мёртвый код (`openMobileNav`,
  `closeMobileNav`, `updateMobileNavActive`, CSS `.mobile-nav-*`/`.nav-btn-mobile`)
  удалены, осталось одно согласованное меню на все точки входа

## 📋 Чек-лист «подготовительные моменты» перед активным продвижением

Прежде чем вкладываться в привлечение трафика, нужно убедиться, что воронка не «течёт» — иначе деньги
уйдут на привлечение людей, которые всё равно не дойдут до оплаты.

1. **Аналитика реально считает.** После деплоя зайти в Яндекс.Метрику (счётчик `109706942` →
   metrika.yandex.ru) и убедиться, что события `reachGoal` приходят на реальных действиях:
   регистрация → старт триала → клик по оплате → успешная оплата. Без этих данных невозможно понять,
   на каком шаге теряются пользователи и куда вкладывать силы дальше.
2. **Юридические документы актуальны и доступны.** Оферта и Политика конфиденциальности на
   `adervis.ru/docs` — на них ссылается чекбокс согласия при регистрации и карточка «Документы» в поддержке.
3. **Реквизиты приёма платежей верны.** Самозанятый, ИНН `592110786536`, ЮKassa `shopId 1375529` —
   сверить с актуальным налоговым статусом и лимитами самозанятого перед масштабированием оборота.
4. **Письма доходят, а не падают в спам.** Resend подключён, домен `app.adervis.ru` подтверждён
   (DKIM/SPF/MX/DMARC) — стоит на старте проверить доставляемость писем-напоминаний и писем
   подтверждения регистрации на разных почтовых сервисах (Mail.ru, Gmail, Яндекс).
5. **Сбор отзывов настроен и используется.** Карточка «Оставить отзыв» готова — как только появятся
   первые оплатившие клиенты, отправить им персональный запрос; лучшие отзывы (с согласия) —
   на лендинг `adervis.ru` как социальное доказательство для новых посетителей.
6. **Поддержка отвечает быстро.** На старте именно скорость ответа в Telegram (@adervisdigital) и на
   email решает, останется ли пробный пользователь после первого затруднения — стоит держать оба
   канала под регулярным присмотром, особенно в первые недели активного продвижения.

## 📣 Каналы привлечения первых клиентов (организационно, вне кода)

Самый сильный аргумент в продажах — то, что продукт родился из реальной боли действующей студии
(история, которую теперь видно прямо в auth gate):
- Прямой контакт с видеопродакшн-студиями и фрилансерами — нишевые чаты, форумы, сообщества
- Контент про собственный опыт студии ADERVIS («как мы считаем сметы и ведём сделки») — естественно
  подводит к продукту, который из этого опыта вырос
- Партнёрства с площадками и сообществами для фрилансеров/студий
- Лендинг `adervis.ru` — синхронизировать ключевое сообщение с auth gate, чтобы посетитель не терял
  нить между «зачем мне это» на лендинге и «вот что я получаю» при регистрации
