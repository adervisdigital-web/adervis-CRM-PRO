### Пара «поверхность → текст» (правило именования)

Соглашение взято у shadcn/ui (`background` + `foreground`) и приведено к нашим
именам: **у каждой заливки есть свой текстовый цвет, и брать их надо парой.**
Причина не в красоте: цвет заливки почти никогда не годится как цвет текста —
`--green` на белой панели даёт около 2.8:1 и проваливает AA.

| Заливка | Текст на ней | Текст этим цветом на панели |
|---|---|---|
| `--primary` | `--on-color` | `--primary-text` |
| `--tint-*-bg` | — | `--primary-on-tint`, `--text-*` |
| `--green` / `--red` / `--yellow` / `--blue` | `--on-color` | `--text-success` / `--text-danger` / `--text-warning` / `--text-info` |

**Новый цветной элемент заводится сразу парой.** Если текстового варианта нет —
его надо добавить в оба блока тем, а не подбирать литерал на месте.

### Цветовые схемы (акценты)

Кроме тёмной и светлой тем есть пять акцентов: `indigo`, `emerald`, `amber`,
`teal`, `graphite` — атрибут `data-accent` на `<html>`. Они переопределяют
только бренд-переменные (`--primary`, `--primary2`, `--primary-rgb`,
`--primary-text`, `--ring`) — то есть добавлять акценты по одному цвету дёшево,
а вот **компонент, который завёл свой литерал вместо `var(--primary)`, ломает
сразу все пять схем и обе темы**.

### Правила применения цвета

- Акцент (`--primary`) — на один главный интерактивный элемент экрана (CTA)
- Статусные цвета — только по смыслу (зелёный = успех, красный = опасность)
- Контраст: обычный текст ≥ 4.5:1, крупный ≥ 3:1 (WCAG AA). Замер живой, не на
  глаз — `tests/suites/a11y.js` проходит по экранам и считает пары
- Чистый `#ffffff` на `#000000` не используем — слишком резко
- Прозрачность (`--panel`, `--line`) считается ПОВЕРХ фона: проверять цвет на той
  поверхности, где он реально лежит, а не на белом листе

## 4. Spacing (отступы)

Шаг шкалы — **2px**, не 4px. Это описание приведено в соответствие с кодом
13.08.2026: раньше здесь была объявлена «строгая шкала 4/8/12/16/24/32/48/64 —
только эти значения», и она не выполнялась ни на одном экране.

Замер по style.css (padding / margin / gap): **10px — самое частое значение в
файле, 127 раз**; 8px — 94, 12px — 75, 6px — 72, 4px — 63, 14px — 58, 2px — 56,
16px — 53, 5px — 32, 18px — 28, 7px — 27, 9px — 20. То есть «вне шкалы»
оказывалось больше значений, чем внутри неё, и самое употребимое из них — 10px.

Переписывать под документ пришлось бы около 380 значений, изменив вид почти
каждого экрана ради правила, которое никто не соблюдал. Правило исправлено под
факт: **шаг 2px, значения кратны двум**. Нечётные (3, 5, 7, 9) — точечные
компенсации оптики (зазор у иконки, подгонка базовой линии), их немного и
плодить их не нужно.

```
2px   — микрозазор: точка статуса и текст, иконка в капсуле
4px   — gap внутри badge, inline-элементы
6px   — gap в плотных строках, чипы фильтров
8px   — label и поле, мелкие отступы
10px  — самый ходовой отступ: padding строк, gap в карточках
12px  — padding кнопки, внутри chip
14px  — padding карточки в плотных списках
16px  — padding панели, отступы в форме
18px  — padding шапки сделки и заголовков секций
24px  — gap между карточками
32px  — отступы страницы, section-gap
```

> **Переменных `--sp-*` НЕ СУЩЕСТВУЕТ.** Здесь много месяцев висел блок `:root`
> с `--sp-1 … --sp-16`, которого нет в style.css ни в каком виде. Он опасен не
> тем, что бесполезен: `padding: var(--sp-2)` при отсутствующей переменной
> заставляет браузер МОЛЧА отбросить объявление целиком, и отступ становится
> нулевым. Ровно так в этом приложении однажды пропал фон у всплывашки
> онбординг-тура (`var(--card)`), и она рисовалась прозрачной.
> Отступы задаются числом в px. Сторож на ссылки к несуществующим токенам —
> в `tests/suites/assets.js`.

## 6. Компоненты — правила

> Значения ниже сняты с `style.css` 19.08.2026. Раньше здесь стоял другой набор:
> кнопка «padding 12px 24px, radius 8px, min-width 120px», карточка на
> `var(--bg3)` с литеральной тенью. Ни одно из этих значений в коде не
> встречалось, а `--bg3` не использовался вообще нигде. Живьём всё это видно на
> витрине (§11).

### Кнопки — `.btn`

```css
.btn {
  border: 1px solid var(--line);
  border-radius: var(--r-lg);       /* 12px */
  padding: 9px 13px;
  min-height: var(--h-md);          /* 44px — цель касания */
  display: inline-flex; align-items: center; gap: 7px;
}
.btn:hover { background: rgb(var(--primary-rgb) / .1); border-color: rgb(var(--primary-rgb) / .55); }
```

Варианты — классом рядом: `.primary` (заливка `--primary`, текст `--on-color`),
`.blue`, `.green`, `.yellow`, `.danger`; размер — `.small`, ширина — `.full`.
Заливку и текст берём **парой** (§3): цвет заливки как цвет текста не годится.

- Минимальная высота 44px — правило, а не пожелание: сторож меряет живой DOM
- `cursor: pointer` только на `<button>` и `<a>`, не навешивать скриптом
- Иконка внутри — `<svg>` 15×15, эмодзи в интерфейсе запрещены

### Поверхности — `.panel` и карточки

Одно правило красит `.panel`, `.item`, `.package-card`, `.project-card`,
`.client-card`, `.task-card`, `.finance-card`, `.team-card`, `.calendar-card`,
`.crm-card`, `.proposal-preview`:

```css
background: var(--panel);
border: 1px solid var(--line);
border-radius: var(--r-xl);       /* 16px */
box-shadow: var(--shadow);        /* = --elev-2 */
```

Новая карточка добавляется **в этот список**, а не заводит свою заливку: иначе
она выпадет из светлой темы и из пяти цветовых схем сразу.

### Поля — `input`, `select`, `textarea`

```css
width: 100%;
border: 1px solid var(--line);
border-radius: var(--r-sm);       /* 8px */
padding: 10px 12px;
background: var(--input);
color: var(--text);
min-height: var(--h-md);          /* кроме textarea: её высоту задаёт содержимое */
```

Фокус — общий для всего приложения и только с клавиатуры:

```css
:focus-visible { outline: var(--ring-w) solid var(--ring); }
```

`:focus` вместо `:focus-visible` не использовать — рамка появится и на клике
мышью. Чекбоксы и радио выведены из правила `width: 100%` отдельно: однажды
квадрат согласия растянулся на 266px и дал горизонтальную прокрутку в КП на
телефоне.

### Числа и суммы

```css
font-family: var(--font-display);   /* Space Grotesk */
font-weight: 700;
font-variant-numeric: tabular-nums;
letter-spacing: -0.02em;
```

`tabular-nums` обязателен везде, где числа стоят в столбец: без него цифры
разной ширины, и колонка сумм «пляшет».

## 7. Motion (анимации)

- **Duration:** 150ms (micro), 250ms (transition), 400ms (modal/sheet)
- **Easing:** `cubic-bezier(0.4, 0, 0.2, 1)` — Material standard
- Skeleton shimmer: `1.5s` infinite
- **Запрет:** никакого `animation: spin` на кнопках (это loading → spinner отдельный элемент)
- `prefers-reduced-motion` — обязательно обрабатывать

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 8. Иконки

- Библиотека: **Lucide** (уже внедряемая тенденция) или inline SVG
- Размер: 16px (inline), 20px (nav/button), 24px (featured)
- Цвет: наследовать `currentColor`
- Никогда не масштабировать PNG иконки

### !important — разбор (03.07.2026)

Убраны 3 избыточных (`input.input-error`, `.scroll-top-btn:hover`, `#adminTopbar` —
специфичность уже побеждала без них). Остальные ~36 — **осознанно оставлены**:
большая часть кода написана в порядке «адаптивный оверрайд объявлен РАНЬШЕ базового
правила компонента» (например, `.topbar{display:flex}` в `@media(min-width:769px)`

**Технический долг**: если когда-нибудь будет большая реорганизация CSS — переставить

большинство этих `!important` станут не нужны. Не делать это сейчас — слишком высокий
риск визуальной регрессии ради косметической выгоды (нарушение "surgical changes").

## 11. Витрина компонентов

`tests/styleguide.html` — одна страница, на которой видна вся система: токены,
типографика, шкала отступов, кнопки, поля, поверхности, бейджи, таблица сумм.
Открывается без всякой сборки (`node tests/server.js` или Live Server) и
подключает НАСТОЯЩИЙ `style.css`, а не копию.

- **Значения токенов страница читает из CSSOM**, а не хранит у себя. Поэтому она
  не может разойтись с кодом так, как разошёлся §3: новый токен появляется на
  витрине сам, удалённый исчезает.
- Переключатели темы и акцента наверху — одна страница показывает все 12
  сочетаний (2 темы × 6 схем). Снимки всех сочетаний: `node tests/styleguide-shot.js`.
- Витрина — рабочий инструмент, а не часть продукта: в `sw.js` не кэшируется и
  ниоткуда из приложения не открывается.

**Зачем.** Идея взята у Storybook (мастерская компонентов и витрина состояний), но
сам Storybook требует npm и сборщика, а проект намеренно без `package.json`
(CLAUDE.md §8) — поэтому взят принцип, а не инструмент. Польза первого же запуска:
нашлись мёртвый токен `--bg3` (не использован нигде и не переопределён в светлой
теме) и расхождение всей палитры §3 с кодом.

## 12. Чего мы НЕ берём из внешних систем

| Источник | Что взяли | Почему не берём целиком |
|---|---|---|
| shadcn/ui | соглашение «пара заливка → текст» (§3) | React + Tailwind + CLI; у нас vanilla без сборки |
| 21st.dev | ничего кодом | компоненты в формате реестра shadcn, то есть React |
| tweakcn | подтверждение подхода «тема = переопределение переменных» | генерирует темы для shadcn; наши акценты устроены так же |
| Storybook | идея витрины (§11) | требует npm и сборщика |
| Refero, Mobbin | референсы глазами | галереи, кода не отдают |

Правило: **берём принцип, а не зависимость.** Каждый из этих инструментов тянет за
собой сборку, которой в проекте сознательно нет: PWA и Service Worker рассчитаны на
один файл `app.js` (CLAUDE.md §8).
