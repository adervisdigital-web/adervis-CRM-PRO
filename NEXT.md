**Сравнивать свой экран с экраном заказчика.** Одни и те же данные рисуются двумя

проверены, в двух нашлись баги.

**Второй приём — искать ОДИН класс дефекта во всех местах сразу, а не чинить точку.**
07.08 жалоба была про одну сетку; пробник по всем вкладкам и разделам показал ту же
болезнь этажом выше. Симметрично: 06.08 починка каталога сломала пакеты, потому что обе
вкладки рисуют одну `<aside>`. **Прежде чем править общий класс — сними замер на всех
экранах, где он живёт.**

**Третий:** грепнуть прямые обращения к константе там, где везде ходят через
функцию-обёртку (`BASE_ITEMS` дал три вхождения, лишнее было видно сразу).

**Четвёртый:** перед правкой прочитать СОСЕДНЮЮ функцию, а не только ту, что правишь.

## Грабли, на которые уже наступили (не наступать снова)

- **Тест должен падать без фикса — проверять руками, по каждой правке отдельно.** Уже
  трижды писал зелёный тест при сломанном коде. Приём: `git stash push -- <файл>`,
  прогон, `git stash pop`.
- **Замер по регекспу врёт в обе стороны** (насчитал 253 поля вместо 36 и 52 клика
  вместо 135). Числа брать Playwright-пробником по живому DOM и закреплять тестом.
- **Замер тоже не всё видит**: перекрытие элемента чужим слоем ловится только
  `elementFromPoint`, а не рамкой. Один раз это поймал скриншот, а не число.
- **Медиазапрос для раскладки ВНУТРИ панели врёт** — ширина панели за окном не следует.
  Брать `@container`. Себя контейнер запросить не может (правила внутри матчат только
  потомков), поэтому меняй `grid-column`/`span` у детей.
- **Мобильный замер без `hasTouch` врёт**: Chromium даёт `pointer:fine`, и блок
  `@media (hover:none) and (pointer:coarse)` не применяется. У `bootLocal` есть `touch: true`.
- **Путь записи в Supabase тестами НЕ ПОКРЫТ**: тесты идут в local mode, где `_supabase`
  нет вовсе. Для «схема не совпала с тем, что шлёт клиент» сторож только статический.
- **`render()` возвращает фокус по `id`, но только для input/textarea/select** — проверка
  «фокус вернулся» через Enter проходит даже с вырезанным кодом, тестировать кнопкой.
- **Статус сделки — только через `_applyCrmStatus`**: он живёт в трёх местах
  (top-level, snapshot, `state.project`), прямое присваивание молча откатывается.
- **Элемент сетки не сжимается ниже `min-content`**, а у `<select>` это его самая длинная
  опция. `min-width: 0` ставить на сам элемент сетки.
- **Контраст — порог, а не оценка.** Цель 5–8:1, перестараться так же плохо.
- **Нужны ОБА `revoke` — `from public` И `from anon`.** 404 на RPC ничего не доказывает —
  добиваться 401 с телом `permission denied`.
- **community-сборка `xlsx` не пишет `cell.s`** — оформление умеет только `xlsx-js-style`.
- В PowerShell **не лепить `2>&1` к git/node**: stderr оборачивается в ErrorRecord, и
  успешная команда выглядит упавшей.
- Менял `app.js`/`style.css`/`index.html` → подними `CACHE_NAME` в `sw.js`. CI проверяет.

## Идеи, до которых не дошли руки

- **Пустые состояния экрана «Финансы» врут на новой сделке**: «Долг 0 ₽ / Закрыто» при

- Договор: шаблоны с `{{токенами}}` покрывают не все поля — `{{срок оплаты}}`,

  человека, часть можно вытащить из сметы.
- Легаси-строки монтажа: миграция кладёт `sourcePacks` и в `cameraCount`, и в
  `sourceCount` — на старой строке с `sourcePacks > 1` надбавка берётся дважды.
- Расход «Налог» не пересчитывается при правке платежа, от которого он посчитан
  (нашлось на разборе долга 60 ₽: 1 136 ₽ вместо 1 140 ₽).
- КП, созданные между 04.07 и накатом миграции 03.08, лежат с `project_id = null` —
  строка в «Все КП» их сделку не откроет. Кодом не связать, только пересоздать.
- Ещё не проверенные парой «свой экран ↔ экран клиента»: встраиваемый калькулятор ↔

## Как здесь принято работать

- Отвечать **по-русски**. Владелец тестирует правки на телефоне почти в реалтайме —
  повторный скриншот через минуту после фикса это норма, не повод торопиться с выводами.
- Цикл: правка → `node tests/run.js` → скриншот/пробник по живому DOM → коммит →
  `git push origin main` → дождаться CI → проверить, что прод отдаёт новый SW.
- **Мерить, а не гадать.** Ожидаемые числа в тестах брать замером, а не арифметикой на
  бумаге.
- Прод-SQL — только с явного разрешения, через `supabase db query --linked`.
  `db advisors --linked` можно свободно.
- Комментарии в коде объясняют ПОЧЕМУ так, а не что делает строка; если правка чинит
  баг — в комментарии остаётся, чем он проявлялся, и с какими числами.
