## Грабли, на которые уже наступили (не наступать снова)

- **Путь записи в Supabase тестами НЕ ПОКРЫТ**: тесты идут в local mode, где
  `_supabase` нет вовсе. Для «схема не совпала с тем, что шлёт клиент» сторож
  только статический.
- **Тест должен падать без фикса — проверяй руками, по каждой правке отдельно.**
  Уже трижды писал зелёный тест при сломанном коде.
- **`render()` сам возвращает фокус по `id`, но только для input/textarea/select.**
  Поэтому проверка «фокус вернулся» через Enter проходит даже с вырезанным кодом —
  тестировать кнопочным путём.
- **Статус сделки — только через `_applyCrmStatus`**: он живёт в трёх местах
  (top-level, snapshot, `state.project`), прямое присваивание молча откатывается.
- **Элемент сетки не сжимается ниже `min-content`**, а у `<select>` это его самая
  длинная опция. `min-width:0` ставить на сам элемент сетки.
- **Разметка не должна зависеть от имени функции в `onclick`** (было `data-deal-id`).
- **Контраст — порог, а не оценка.** Цель 5–8:1.
- **Нужны ОБА `revoke` — `from public` И `from anon`.** 404 на RPC ничего не
  доказывает («нет функции с такими именами аргументов») — добиваться 401.
- **community-сборка `xlsx` не пишет `cell.s`** — оформление умеет только
  `xlsx-js-style`, заливке нужен явный `patternType: "solid"`.
- Менял `app.js`/`style.css`/`index.html` → подними `CACHE_NAME` в `sw.js`.

## Как здесь принято работать

- Отвечать **по-русски**. Владелец тестирует правки на телефоне почти в реалтайме.
- Цикл: правка → `node tests/run.js` → скриншот/пробник по живому DOM → коммит →
  `git push origin main` → дождаться CI → проверить, что прод отдаёт новый SW.
- Мерить, а не гадать: регексп по исходнику врёт в обе стороны, числа брать
  Playwright-пробником по живому DOM и закреплять тестом.
- Прод-SQL — только с явного разрешения, гоняется через `supabase db query --linked`.
  `db advisors --linked` можно свободно.
- Комментарии в коде объясняют ПОЧЕМУ так, а не что делает строка; если правка
  чинит баг — в комментарии остаётся, чем он проявлялся.
